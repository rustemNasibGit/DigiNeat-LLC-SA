Сводная таблица эндпоинтов
Метод	Эндпоинт	Описание
POST	/api/v1/auth/register	Регистрация нового пользователя
POST	/api/v1/auth/verify-email	Подтверждение email по токену из письма
POST	/api/v1/auth/login	Аутентификация (вход в систему)
POST	/api/v1/auth/logout	Выход из системы
GET	/api/v1/user/profile	Получение профиля (проверка авторизации)
🛠 Спецификация эндпоинтов
1. Регистрация пользователя
Создает учетную запись в статусе «не подтверждена» и инициирует отправку email.
• URL: /api/v1/auth/register
• Метод: POST
• Тело запроса (JSON):
json
{
  "email": "user@example.com",
  "password": "StrongPassword123",
  "name": "Иван"
}
Используйте код с осторожностью.
• Коды ответов:
	• 201 Created — Пользователь успешно создан, письмо отправлено.
	• 400 Bad Request — Неверный формат email, пароль не соответствует политике безопасности, или имя не заполнено.
	• 409 Conflict — Пользователь с таким email уже существует.
2. Подтверждение email
Активирует аккаунт пользователя. Ссылка в письме должна вести на фронтенд-страницу, которая извлекает токен из URL и отправляет его на этот эндпоинт.
• URL: /api/v1/auth/verify-email
• Метод: POST
• Тело запроса (JSON):
json
{
  "token": "уникальный_одноразовый_токен_из_письма"
}
Используйте код с осторожностью.
• Коды ответов:
	• 200 OK — Email успешно подтвержден. Аккаунт активирован.
	• 400 Bad Request — Токен недействителен, устарел или уже был использован.
3. Авторизация (Вход)
Проверяет учетные данные. Рекомендуется использовать механизм HttpOnly, Secure, SameSite=Strict Cookies для хранения сессии/токена (защита от XSS).
• URL: /api/v1/auth/login
• Метод: POST
• Тело запроса (JSON):
json
{
  "email": "user@example.com",
  "password": "StrongPassword123"
}
Используйте код с осторожностью.
• Коды ответов:
	• 200 OK — Успешный вход. В ответе (или в Cookie) передается идентификатор сессии / JWT-токен.
	• 401 Unauthorized — Неверный логин или пароль.
	• 403 Forbidden — Email еще не подтвержден.
4. Выход (Logout)
Инвалидирует текущую сессию пользователя.
• URL: /api/v1/auth/logout
• Метод: POST
• Заголовки: Требуется авторизация (Cookie или Authorization Header).
• Коды ответов:
	• 200 OK — Сессия успешно завершена, Cookie/токен удалены.
	• 401 Unauthorized — Пользователь не был авторизован.
5. Получение профиля (Личный кабинет)
Пример защищенного эндпоинта для проверки статуса авторизации и отображения данных.
• URL: /api/v1/user/profile
• Метод: GET
• Заголовки: Требуется авторизация.
• Тело ответа (JSON):
json
{
  "id": 123,
  "email": "user@example.com",
  "name": "Иван"
}
Используйте код с осторожностью.
• Коды ответов:
	• 200 OK — Данные успешно получены.
	• 401 Unauthorized — Доступ запрещен (сессия отсутствует или истекла).
🔒 Общие нефункциональные требования
• Безопасность паролей: Пароли должны хешироваться в БД с использованием стойких алгоритмов (например, BCrypt или Argon2). Хранение в открытом виде запрещено.
• Генерация токенов: Токен подтверждения почты должен быть криптографически стойким, иметь ограниченный срок действия (например, 24 часа) и удаляться/инвалидироваться после первого использования.
• Защита от брутфорса: На эндпоинты /login и /register необходимо установить Rate Limiting (ограничение количества запросов с одного IP-адреса в единицу времени).
